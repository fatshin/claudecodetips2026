最近触ったコード（または$ARGUMENTSで指定された範囲）を**簡素化**する提案を作る。

# 動作

3つの観点で並列レビュー：

1. **重複削減**: DRY原則違反、似た関数の統合候補
2. **コード品質**: 命名、関数長、ネスト深さ、cognitive complexity
3. **効率**: 不要な計算、N+1、メモ化候補、O(n²)→O(n)

各観点を別subagent（または同じcode-reviewerで複数回）として実行し、提案を集約。

# 手順

1. 対象範囲確定
   - $ARGUMENTS あれば使用
   - 無ければ `git diff HEAD~5..HEAD --stat` で直近5コミットの変更ファイル

2. 各ファイルに対して以下のプロンプトでcode-reviewer起動:

```
以下の観点でリファクタ提案を出せ:

【観点1: 重複削減】
- 同じロジックの繰り返し
- 似た関数の統合候補
- 共通化できる定数・型

【観点2: コード品質】
- 命名の改善余地
- 関数長（30行超は要注意）
- ネスト深さ（3階以上は要注意）
- cognitive complexity（15超は要注意）

【観点3: 効率】
- 不要な計算（ループ内での変化しない値）
- N+1パターン
- メモ化候補（純粋関数で重い計算）
- アルゴリズムの計算量

各提案について:
- 該当箇所: [file:line]
- 現状: ...
- 提案: ...
- 工数見積: xs/s/m
- リスク: low/medium/high
- 期待効果: ...
```

3. 集約して優先度順に提示

# 出力フォーマット

```markdown
# Simplification Proposals

対象: $ARGUMENTS（または「直近5コミット」）

## サマリー
- 提案数: N件
- 即実行推奨（low risk + s工数）: M件
- 慎重に検討（medium risk以上）: K件

## 即実行推奨

### #1: [タイトル]
- ファイル: src/foo.ts:42-58
- 現状: 同じif文が3か所
- 提案: 共通関数に抽出
- 工数: s（半日）
- リスク: low
- 効果: コード行数 -15%、保守性向上

### #2: ...

## 慎重に検討

### #N: [タイトル]
（同様）

## 採用見送りでよい候補
- ...（理由）

## 自動修正可能なもの
- prettier / eslint --fix で対応可能なもの → 既存hookで自動化済
- 残りの手動修正対象: M件
```

# 使い方

```
/simplify                              # 直近5コミット
/simplify src/billing                  # billing配下全体
/simplify diff main..feature           # 特定ブランチ差分
/simplify file src/auth/middleware.ts  # 単一ファイル
```

# 注意

- 提案を**鵜呑みにしない**。リスクlowでもテストが守ってない箇所は要注意
- 大量の提案が出ても一度に修正しない。1 PRで1〜3提案が現実的
- 簡素化のための簡素化は罪。**実害があるもの**のみ採用
