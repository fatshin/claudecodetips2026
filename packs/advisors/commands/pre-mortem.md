$ARGUMENTS について Pre-mortem（事前死亡診断）を実施。

# Pre-mortem の発想

「6か月後／1年後にこのプロジェクトが失敗していたと仮定する。
原因として最もありえる5つを挙げ、現時点で何ができるか考える」

ケネディ式の意思決定支援。**事後ではなく事前に失敗シナリオを想像することで盲点を潰す**。

# 手順

1. 対象を読み取り
2. 4つのadvisorを並列起動し、それぞれに以下を依頼:
   - principal: 6か月後に失敗していたら、アーキ的な原因は？
   - security: 失敗の原因がセキュリティ事故だったら？
   - cost: 失敗の原因がコスト超過だったら？
   - product: 失敗の原因がユーザーに使われなかったことだったら？

3. 各5シナリオずつ × 4 advisor = 計20シナリオを集約
4. 確からしさ × インパクト で優先順位付け
5. 上位5シナリオに対する事前対策を提案

# 使い方の例

```
/pre-mortem JACCS krox/WebEntry のpaperless化proposal
/pre-mortem Mirumiru Project の事業化計画
/pre-mortem 100k stocks AI monitoring system v4.3 → v5.0 移行
```

# 注意

- 楽観的になりがちな計画レビューに対する**意図的な悲観的視点**を与える
- 失敗を前提に考えることで盲点が見える
- すべてのシナリオが起きるわけではないが、**起きた時の対応コスト**が事前に見える
